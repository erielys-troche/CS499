Software design and engineering: Global Rain

A Java pet check-out program from IT 145, refactored with the Strategy pattern.

The original artifact

My artifact for this category is the Global Rain pet check-out program IT 145 (Foundations in Application Development), which I originally wrote in Java. It’s a small console program for a fictional pet boarding company, and it calculates a grooming fee and a stay fee for a pet based on its type (dog or cat), its weight, and how many days it’s staying, then it adds those up into a total. It uses a base Pet class and a Dog subclass to show some basic object-oriented programming, like inheritance and polymorphism.

Why I chose it

I picked this one for the software design and engineering category because it’s a clean example of OOP, but it was also honestly kind of rough around the edges once I looked at it again with fresh eyes during my code review. The fee amounts were just hardcoded numbers scattered through if-else statements, there was no input validation at all, and there were no tests, so the only way to know if it worked was to run it and eyeball the output.

The enhancement

For the enhancement, I refactored the fee logic out of the Pet and Dog classes and into a Strategy pattern instead. Now there’s a FeeStrategy interface, with a DogFeeStrategy and a CatFeeStrategy that each handle their own pricing rules. This means if Global Rain ever wanted to add a new pet type, such as a bird, I’d just write a new strategy class instead of going back and editing the existing Pet/ Dog code. I also replaced all the magic numbers with named constants, added real input validation so a negative weight or stay length throws a clear error instead of quietly producing a wrong fee, and wrote a JUnit test suite that checks the fee boundaries (something like exactly 20 or 30 pounds, and a 2-day grooming cut-off) along with the new validation. I think this shows I can take a working-but-messy piece of code and actually restructure it using a real design pattern, not just patch it.

Course outcomes

Going into this, I was aiming for outcomes number two, three, four, and five, and I think this enhancement lines up with all four. The strategy pattern refactor is outcome number three, since I had to think through a real design trade-off between keeping things simple and making the code flexible for future pet types. Using JUnit is outcome four, since it’s a well-founded testing tool I had not actually used in the original version. The input validation would be considered outcome number five, closing a real gap where bad data could have been accepted silently. And writing this narrative, plus commenting the new code clearly, is outcome two. I don’t think I have updates to my outcome coverage plan from Module one, this enhancement ended up matching pretty closely to what I originally planned.

Outcomes met, partly met, and not met: I met outcome three (design trade-off with the Strategy pattern), outcome four (JUnit testing), and outcome five (input validation). I partly met outcome two, because I explained the design in writing and comments, but I haven't had another developer review it. I did not fully meet one thing: I wasn't able to compile and run the Java enhancement and its JUnit tests in my capstone workspace, so I can't say for sure they pass yet. I plan to run them in my IDE.

What I learned

Going back into old code I wrote a while ago was pretty humbling. It is much easier to see now how much I was trying to get something working instead of thinking about how it would hold up if requirements changed. The biggest challenge was actually resisting the urge to just clean up the if-else statements instead of doing a real structural change, it would have been faster to just add a few comments and call it done, but that wouldn’t have actually shown growth. Writing the JUnit test also made me realize how many edge cases I never thought about the first time around, like what happens right at the 20-pound cutoff. Overall, these enhancements didn’t just make the code better, it also made me think more carefully about how I structure things from the start.

Incorporating feedback

My instructor gave this milestone a 100%, so I didn’t make any changes to it. I did, however, reread the comments and used them as a check that the strategy pattern design was heading in the right direction.

Pet.java
/**
 * Pet.java
 * Original artifact from IT 145 (Global Rain).
 *
 * Base class for all pets in the Global Rain boarding system. Provides
 * default fee calculations (used as-is for cats) that the Dog subclass
 * overrides with weight-based pricing.
 */
public class Pet {
    private String name;
    private double weight;
    private int stayDays;

    public Pet(String name, double weight, int stayDays) {
        this.name = name;
        this.weight = weight;
        this.stayDays = stayDays;
    }

    public String getName() {
        return name;
    }

    public double getWeight() {
        return weight;
    }

    public int getStayDays() {
        return stayDays;
    }

    // Default grooming fee. Cats are not groomed, so this is 0.
    public double calculateGroomingFee() {
        return 0.0;
    }

    // Default stay fee. Used by cats.
    public double calculateStayFee() {
        return 18.00;
    }

    public double getTotalFee() {
        return calculateGroomingFee() + calculateStayFee();
    }
}
Dog.java
/**
 * Dog.java
 * Original artifact from IT 145 (Global Rain).
 *
 * Subclass of Pet with dog-specific fee calculations based on weight.
 *
 * NOTE (flagged in the Milestone One code review): fee amounts below are
 * hardcoded "magic numbers" instead of named constants, and there is no
 * validation of weight or stayDays, so invalid input (e.g. a negative
 * weight) would silently produce a fee instead of raising an error.
 */
public class Dog extends Pet {

    public Dog(String name, double weight, int stayDays) {
        super(name, weight, stayDays);
    }

    @Override
    public double calculateGroomingFee() {
        if (getStayDays() < 2) {
            return 0.0;
        }
        if (getWeight() < 20) {
            return 19.95;
        } else if (getWeight() < 30) {
            return 24.95;
        } else {
            return 29.95;
        }
    }

    @Override
    public double calculateStayFee() {
        if (getWeight() < 20) {
            return 24.00;
        } else if (getWeight() < 30) {
            return 29.00;
        } else {
            return 34.00;
        }
    }
}

Enhanced

FeeStrategy.java
/**
 * FeeStrategy.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * Strategy interface for computing a pet's grooming and stay fees. This
 * pulls fee logic out of the Pet class hierarchy so new pricing rules,
 * or an entirely new pet type, can be added by writing a new strategy
 * class instead of modifying existing ones. This directly addresses the
 * extensibility weakness flagged in the Milestone One code review.
 */
public interface FeeStrategy {
    double calculateGroomingFee(Pet pet);
    double calculateStayFee(Pet pet);
}
DogFeeStrategy.java
/**
 * DogFeeStrategy.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * Fee rules for dogs, based on weight and length of stay. The magic
 * numbers from the original Dog class have been replaced with named
 * constants, so the fee schedule is self-documenting and can be updated
 * in one place instead of hunting through if-else branches.
 */
public class DogFeeStrategy implements FeeStrategy {

    private static final double SMALL_DOG_GROOMING_FEE = 19.95;
    private static final double MEDIUM_DOG_GROOMING_FEE = 24.95;
    private static final double LARGE_DOG_GROOMING_FEE = 29.95;

    private static final double SMALL_DOG_STAY_FEE = 24.00;
    private static final double MEDIUM_DOG_STAY_FEE = 29.00;
    private static final double LARGE_DOG_STAY_FEE = 34.00;

    private static final double SMALL_MEDIUM_WEIGHT_THRESHOLD = 20.0;
    private static final double MEDIUM_LARGE_WEIGHT_THRESHOLD = 30.0;
    private static final int MINIMUM_STAY_FOR_GROOMING = 2;

    @Override
    public double calculateGroomingFee(Pet pet) {
        if (pet.getStayDays() < MINIMUM_STAY_FOR_GROOMING) {
            return 0.0;
        }
        if (pet.getWeight() < SMALL_MEDIUM_WEIGHT_THRESHOLD) {
            return SMALL_DOG_GROOMING_FEE;
        } else if (pet.getWeight() < MEDIUM_LARGE_WEIGHT_THRESHOLD) {
            return MEDIUM_DOG_GROOMING_FEE;
        } else {
            return LARGE_DOG_GROOMING_FEE;
        }
    }

    @Override
    public double calculateStayFee(Pet pet) {
        if (pet.getWeight() < SMALL_MEDIUM_WEIGHT_THRESHOLD) {
            return SMALL_DOG_STAY_FEE;
        } else if (pet.getWeight() < MEDIUM_LARGE_WEIGHT_THRESHOLD) {
            return MEDIUM_DOG_STAY_FEE;
        } else {
            return LARGE_DOG_STAY_FEE;
        }
    }
}
CatFeeStrategy.java
/**
 * CatFeeStrategy.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * Fee rules for cats: no grooming fee, flat stay fee. Previously this
 * logic lived as "default" behavior on the Pet base class itself, which
 * mixed "what a cat is" with "how a cat is priced." Pulling it into its
 * own strategy keeps that separation clean.
 */
public class CatFeeStrategy implements FeeStrategy {

    private static final double CAT_STAY_FEE = 18.00;

    @Override
    public double calculateGroomingFee(Pet pet) {
        return 0.0;
    }

    @Override
    public double calculateStayFee(Pet pet) {
        return CAT_STAY_FEE;
    }
}
Pet.java
/**
 * Pet.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * Base class for all pets in the Global Rain boarding system.
 *
 * Two enhancements over the original artifact:
 *  1. The constructor now validates its inputs and throws
 *     IllegalArgumentException on bad data, instead of silently
 *     accepting a negative weight or stay length.
 *  2. Fee calculation is delegated to a FeeStrategy (Strategy design
 *     pattern) instead of being implemented directly on Pet/Dog.
 */
public class Pet {
    private final String name;
    private final double weight;
    private final int stayDays;
    private final FeeStrategy feeStrategy;

    public Pet(String name, double weight, int stayDays, FeeStrategy feeStrategy) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException("Pet name cannot be empty.");
        }
        if (weight <= 0) {
            throw new IllegalArgumentException("Pet weight must be greater than zero.");
        }
        if (stayDays < 0) {
            throw new IllegalArgumentException("Stay length cannot be negative.");
        }
        this.name = name;
        this.weight = weight;
        this.stayDays = stayDays;
        this.feeStrategy = feeStrategy;
    }

    public String getName() {
        return name;
    }

    public double getWeight() {
        return weight;
    }

    public int getStayDays() {
        return stayDays;
    }

    public double calculateGroomingFee() {
        return feeStrategy.calculateGroomingFee(this);
    }

    public double calculateStayFee() {
        return feeStrategy.calculateStayFee(this);
    }

    public double getTotalFee() {
        return calculateGroomingFee() + calculateStayFee();
    }
}

Main.java
import java.util.ArrayList;
import java.util.List;

/**
 * Main.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * Demonstrates the enhanced Global Rain fee calculator, including the
 * input validation added in this milestone.
 */
public class Main {
    public static void main(String[] args) {
        List<Pet> pets = new ArrayList<Pet>();
        pets.add(new Dog("Rex", 45, 3));
        pets.add(new Cat("Whiskers", 9, 4));
        pets.add(new Dog("Milo", 15, 1));

        for (Pet pet : pets) {
            System.out.printf("%s: $%.2f%n", pet.getName(), pet.getTotalFee());
        }

        // Demonstrates the new validation. In the original version, this
        // would have silently produced a nonsense fee. Now it fails fast
        // with a clear, human-readable error message instead.
        try {
            Pet invalidPet = new Dog("Buddy", -12, 2);
            System.out.println(invalidPet.getTotalFee());
        } catch (IllegalArgumentException e) {
            System.out.println("Could not check in pet: " + e.getMessage());
        }
    }
}

import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;
import static org.junit.jupiter.api.Assertions.assertThrows;

/**
 * PetTest.java
 * ENHANCEMENT (Milestone Two — Software Design and Engineering).
 *
 * JUnit 5 tests covering the fee boundary conditions identified in the
 * Milestone One code review (20 lb / 30 lb weight cutoffs, 2-day stay
 * cutoff), plus the new input validation. Add the JUnit 5 dependency
 * (org.junit.jupiter:junit-jupiter) to run these in your IDE or with
 * Maven/Gradle.
 */
public class PetTest {

    @Test
    void smallDogGroomingFeeAtBoundary() {
        Dog dog = new Dog("Buddy", 19.99, 3);
        assertEquals(19.95, dog.calculateGroomingFee(), 0.001);
    }

    @Test
    void mediumDogGroomingFeeAtBoundary() {
        Dog dog = new Dog("Duke", 20.0, 3);
        assertEquals(24.95, dog.calculateGroomingFee(), 0.001);
    }

    @Test
    void largeDogGroomingFeeAtBoundary() {
        Dog dog = new Dog("Zeus", 30.0, 3);
        assertEquals(29.95, dog.calculateGroomingFee(), 0.001);
    }

    @Test
    void noGroomingFeeUnderTwoDayStay() {
        Dog dog = new Dog("Milo", 15, 1);
        assertEquals(0.0, dog.calculateGroomingFee(), 0.001);
    }

    @Test
    void catNeverChargedGroomingFee() {
        Cat cat = new Cat("Whiskers", 9, 5);
        assertEquals(0.0, cat.calculateGroomingFee(), 0.001);
    }

    @Test
    void catFlatStayFee() {
        Cat cat = new Cat("Whiskers", 9, 5);
        assertEquals(18.00, cat.calculateStayFee(), 0.001);
    }

    @Test
    void negativeWeightThrowsException() {
        assertThrows(IllegalArgumentException.class, () -> new Dog("Buddy", -5, 2));
    }

    @Test
    void negativeStayDaysThrowsException() {
        assertThrows(IllegalArgumentException.class, () -> new Dog("Buddy", 20, -1));
    }

    @Test
    void emptyNameThrowsException() {
        assertThrows(IllegalArgumentException.class, () -> new Dog("", 20, 2));
    }
}
