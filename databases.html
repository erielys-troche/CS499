Databases: QuantigrationUpdates returns report

A MySQL database from DAD 220, with indexes, stored procedures, and an automated Python report.

The original artifact

My artifact for this category is the QuantigrationUpdates database from DAD 220 (Introduction to Structured Database Environments), which I built in MySQL around April 2024. It has three tables, Customers (later renamed ‘Collaborator’), Orders, and RMA, connected with primary and foreign keys. I loaded about 38,000 rows of CSV data into it, wrote queries for counts, joins, updates, and deletes, and then wrote a short report for a product manager about returns by state and by product.

Why I chose it

I chose this one because it’s the only project where I worked with a real-sized dataset, and because the end result was a report meant for an actual decision-maker. But looking back at it, everything was done by hand. I typed each query into the terminal, took a screenshot, and pasted it into a Word document, so if a manager wanted updated numbers next month, I would have had to do the whole thing over again.

The enhancement

For enhancement, I improved the database itself and then automated the reporting on top of it. On the database side, I wrote a SQL script, then added indexes on the columns I actually filter and group by (State, SKU, and Status), a view for returns that aren’t complete yet, and four stored procedures that replace the hand-typed queries. One of the procedures takes a parameter, so the value is never pasted into the SQL text. I also added a read-only account that can only run those procedures and read the view, so the report can’t change or delete any data. On the Python side, I wrote a script using pandas and matplotlib that calls the procedures, calculates summary statistics, makes charts, and writes an HTML report on its own. I also redefined the product return percentage so it’s each product’s own orders, which makes it a real return rate and easier to interpret than what I had in Project Two. To test it, I wrote six unit tests, including one that tries to sneak a DROP TABLE command in through the state parameter and confirms the table is still there afterward.

Course outcomes

I planned to hit outcomes number one, three, four, and five with this enhancement, and I believe I did. For outcome number three, I had to think about the trade-offs of indexing, since indexes make reads faster but add a little work every time data is inserted or changed, and I decided it was worth it because this data is read much more than it’s written. For outcome number four, I used Python, pandas, and stored procedures, which were new tools compared to the original project. For outcome number five, I used parameterized queries, a least-privilege account, and environment variables for the login info so no password is ever written in the code. And for outcome number one, the whole point of the automated report is to give a product manager something clear they can use to make decisions without needing to understand SQL. I don’t have any updates to my outcome plan from Module One.

Outcomes met, partly met, and not met: I met outcomes three (indexing trade-offs), four (Python, pandas, and stored procedures), and five (parameterized queries, a read-only account, and environment variables for login info). I partly met outcome one, because the report is written for a product manager but I haven't tested it on a real one.

What I learned

The biggest thing I learned came from a mistake in my own plan. I had said in my code review that I would add indexes to the foreign key columns because I thought they weren’t indexed. When I went back to my DESCRIBE output from Project One, the Key column already said MUL for both of them, which means MySQL had already created those indexes automatically. So I had to change the plan and index the columns I actually searched and grouped by instead. It was a small thing, but it taught me to check what the database is really doing instead of assuming. Another challenge was deciding what ‘return rate’ should actually mean. My original percentage was hard to explain, and once I tried to write it as a stored procedure, I had to stop and decide what the number was supposed to say. I also added a demo mode to the Python script that builds a small sample database, so the report and the tests can run on any computer without setting up MySQL. That way I could test the logic on its own before connecting it to the real database. The SQL script is written for MySQL, and the report can connect to it with the mysql option once the environment variables are set. Overall, this milestone made me feel like I went from just writing queries to actually building something that other people could use, and that is the kind of work I would like to pursue.

Incorporating feedback

My instructor gave me a 100% and did not request any changes. The one correction I made was in my code review, I said the foreign key columns were not indexed, but my own DESCRIBE output shows MySQL had already indexed them. I changed the plan to index State, SKU, and Status instead, so the code review video and this narrative don’t fully match.

-- A. Number of returns by state
SELECT Collaborator.State, COUNT(*) AS AmountOfReturns
FROM Orders
INNER JOIN RMA ON Orders.OrderID = RMA.OrderID
INNER JOIN Collaborator ON Collaborator.CustomerID = Orders.CustomerID
GROUP BY State
ORDER BY AmountOfReturns DESC;

-- B. Percentage of returns by product type
SELECT
    SKU AS ProductSKU,
    Description AS ProductDescription,
    (COUNT(*) * 100 / (SELECT COUNT(*) FROM Orders WHERE Status = 'Complete')) AS ReturnsPercentage
FROM Orders
INNER JOIN RMA ON Orders.OrderID = RMA.OrderID
WHERE Status = 'Complete'
GROUP BY SKU, Description
ORDER BY ReturnsPercentage DESC;

Enhanced

01_database_enhancements.sql
-- 01_database_enhancements.sql
-- ENHANCEMENT (Milestone Four — Databases)
--
-- Run this ONCE in MySQL (Codio terminal) after the original tables are
-- created and loaded:
--     mysql> SOURCE 01_database_enhancements.sql;
--
-- What this adds to the original artifact:
--   1. Indexes on the columns the analysis actually filters/groups by
--   2. A view for returns that are still open
--   3. Stored procedures for the report queries (one takes a parameter)
--   4. A least-privilege, read-only account for the Python report

USE QuantigrationUpdates;

-- ---------------------------------------------------------------------
-- 1. INDEXES
-- ---------------------------------------------------------------------
-- NOTE: I originally planned to index the foreign key columns
-- (Orders.CustomerID and RMA.OrderID), but DESCRIBE showed "MUL" in the
-- Key column for both -- MySQL (InnoDB) already creates an index on a
-- foreign key automatically. So I index the columns the queries use for
-- WHERE / GROUP BY instead.
--
-- Trade-off: each index speeds up reads on that column but adds a little
-- work to every INSERT/UPDATE/DELETE and uses extra storage. These columns
-- are read far more than they are written, so it's worth it.
--
-- (If you need to re-run this file, drop the indexes first:
--  DROP INDEX idx_collaborator_state ON Collaborator; etc.)
CREATE INDEX idx_collaborator_state ON Collaborator (State);
CREATE INDEX idx_orders_sku         ON Orders (SKU);
CREATE INDEX idx_rma_status         ON RMA (Status);

-- To check whether MySQL actually uses an index, run for example:
--   EXPLAIN SELECT State, COUNT(*) FROM Collaborator GROUP BY State;

-- ---------------------------------------------------------------------
-- 2. VIEW: returns that are not finished yet
-- ---------------------------------------------------------------------
-- Note: rows with a NULL Status are not included because NULL <> 'Complete'
-- is not true in SQL.
CREATE OR REPLACE VIEW ActiveReturnsView AS
SELECT
    r.RMAID,
    r.OrderID,
    r.Status,
    r.Step,
    r.Reason,
    o.SKU,
    c.State
FROM RMA r
INNER JOIN Orders o       ON o.OrderID = r.OrderID
INNER JOIN Collaborator c ON c.CustomerID = o.CustomerID
WHERE r.Status <> 'Complete';

-- ---------------------------------------------------------------------
-- 3. STORED PROCEDURES
-- ---------------------------------------------------------------------
DELIMITER $$

-- Returns by state (replaces the hand-typed query from Project Two)
DROP PROCEDURE IF EXISTS GetReturnsByState$$
CREATE PROCEDURE GetReturnsByState()
BEGIN
    SELECT c.State AS State, COUNT(*) AS AmountOfReturns
    FROM RMA r
    INNER JOIN Orders o       ON o.OrderID = r.OrderID
    INNER JOIN Collaborator c ON c.CustomerID = o.CustomerID
    GROUP BY c.State
    ORDER BY AmountOfReturns DESC;
END$$

-- Return rate by product: returns for a SKU divided by orders for that SKU.
-- (The Project Two version divided by a total instead of by each product's
-- own orders, which made the percentages hard to interpret.)
DROP PROCEDURE IF EXISTS GetReturnRateBySKU$$
CREATE PROCEDURE GetReturnRateBySKU()
BEGIN
    SELECT
        o.SKU AS SKU,
        MAX(o.Description) AS ProductDescription,
        COUNT(DISTINCT o.OrderID) AS TotalOrders,
        COUNT(r.RMAID) AS TotalReturns,
        ROUND(COUNT(r.RMAID) * 100.0 / COUNT(DISTINCT o.OrderID), 2) AS ReturnRatePct
    FROM Orders o
    LEFT JOIN RMA r ON r.OrderID = o.OrderID
    GROUP BY o.SKU
    ORDER BY ReturnRatePct DESC;
END$$

-- Returns by reason
DROP PROCEDURE IF EXISTS GetReturnsByReason$$
CREATE PROCEDURE GetReturnsByReason()
BEGIN
    SELECT COALESCE(Reason, 'Unknown') AS Reason, COUNT(*) AS AmountOfReturns
    FROM RMA
    GROUP BY COALESCE(Reason, 'Unknown')
    ORDER BY AmountOfReturns DESC;
END$$

-- Returns for ONE state, broken down by product. Takes a parameter, so the
-- state value is never pasted into the SQL text (prevents SQL injection).
DROP PROCEDURE IF EXISTS GetReturnsBySkuForState$$
CREATE PROCEDURE GetReturnsBySkuForState(IN p_state VARCHAR(25))
BEGIN
    SELECT o.SKU AS SKU, COUNT(*) AS AmountOfReturns
    FROM RMA r
    INNER JOIN Orders o       ON o.OrderID = r.OrderID
    INNER JOIN Collaborator c ON c.CustomerID = o.CustomerID
    WHERE c.State = p_state
    GROUP BY o.SKU
    ORDER BY AmountOfReturns DESC;
END$$

DELIMITER ;

-- ---------------------------------------------------------------------
-- 4. LEAST-PRIVILEGE ACCOUNT FOR THE PYTHON REPORT
-- ---------------------------------------------------------------------
-- The report only needs to run these procedures and read the view. It does
-- not need (and should not have) permission to change or delete data.
-- Stored procedures run with their creator's rights by default, so this
-- account never needs direct access to the tables.
--
-- CHANGE THE PASSWORD before running. Do not commit a real password to GitHub.
-- (This section is optional if your Codio account can't create users.)
CREATE USER IF NOT EXISTS 'rma_analyst'@'localhost' IDENTIFIED BY 'CHANGE_ME_BEFORE_USE';
GRANT EXECUTE ON PROCEDURE QuantigrationUpdates.GetReturnsByState       TO 'rma_analyst'@'localhost';
GRANT EXECUTE ON PROCEDURE QuantigrationUpdates.GetReturnRateBySKU      TO 'rma_analyst'@'localhost';
GRANT EXECUTE ON PROCEDURE QuantigrationUpdates.GetReturnsByReason      TO 'rma_analyst'@'localhost';
GRANT EXECUTE ON PROCEDURE QuantigrationUpdates.GetReturnsBySkuForState TO 'rma_analyst'@'localhost';
GRANT SELECT ON QuantigrationUpdates.ActiveReturnsView TO 'rma_analyst'@'localhost';

def connect_mysql():
    """Connect to the real MySQL database using environment variables."""
    required = ["DB_HOST", "DB_NAME", "DB_USER", "DB_PASSWORD"]
    missing = [name for name in required if not os.environ.get(name)]
    if missing:
        sys.exit("Missing environment variable(s): " + ", ".join(missing)
                 + "\nSet them first (see README.md), then run again.")
    try:
        from sqlalchemy import create_engine
        from sqlalchemy.engine import URL
    except ImportError:
        sys.exit("mysql mode needs SQLAlchemy and PyMySQL.\n"
                 "Install them with: pip install -r requirements.txt")

    url = URL.create(
        "mysql+pymysql",
        username=os.environ["DB_USER"],
        password=os.environ["DB_PASSWORD"],
        host=os.environ["DB_HOST"],
        port=int(os.environ.get("DB_PORT", "3306")),
        database=os.environ["DB_NAME"],
    )
    return create_engine(url).connect()


def build_demo_database(seed=499):
    """Build a small made-up database with the same tables as the real one."""
    skus = [
        ("BAS-24-1 C", "Basic Switch 10/100/1000 BaseT 24 port", 0.02),
        ("BAS-48-1 C", "Basic Switch 10/100/1000 BaseT 48 port", 0.20),
        ("BAS-08-1 C", "Basic Switch 10/100/1000 BaseT 8 port", 0.10),
        ("ADV-24-10C", "Advanced Switch 10GigE Copper 24 port", 0.10),
        ("ADV-48-10F", "Advanced Switch 10 GigE Copper/Fiber 44 port copper 4 port fiber", 0.10),
        ("ENT-24-10F", "Enterprise Switch 10GigE SFP+ 24 Port", 0.10),
        ("ENT-48-10F", "Enterprise Switch 10GigE SFP+ 48 port", 0.11),
        ("ENT-24-40F", "Enterprise Switch 40GigE SFP+ 24 port", 0.05),
        ("ENT-48-40F", "Enterprise Switch 40GigE SFP+ 48 port", 0.15),
    ]
    states = [
        "Alabama", "Arizona", "Arkansas", "California", "Colorado", "Connecticut",
        "Delaware", "Florida", "Georgia", "Idaho", "Illinois", "Indiana", "Iowa",
        "Kansas", "Kentucky", "Louisiana", "Maine", "Maryland", "Massachusetts",
        "Michigan", "Minnesota", "Mississippi", "Missouri", "Montana", "Nebraska",
        "Nevada", "New Hampshire", "New Jersey", "New Mexico", "New York",
        "North Carolina", "Ohio", "Oklahoma", "Oregon", "Pennsylvania",
        "Rhode Island", "South Carolina", "Tennessee", "Texas", "Utah", "Vermont",
        "Virginia", "Washington", "West Virginia", "Wisconsin", "Wyoming",
    ]
    reasons = ["Defective", "Wrong item", "Not as described", "No longer needed"]
    statuses = ["Complete", "Complete", "Pending", "In Progress"]
    steps = ["Awaiting customer documentation", "Credit customer account", "Item received"]

    rng = random.Random(seed)
    conn = sqlite3.connect(":memory:")
    conn.executescript("""
        CREATE TABLE Collaborator (CustomerID INTEGER PRIMARY KEY, State TEXT);
        CREATE TABLE Orders (OrderID INTEGER PRIMARY KEY, CustomerID INTEGER,
                             SKU TEXT, Description TEXT);
        CREATE TABLE RMA (RMAID INTEGER PRIMARY KEY, OrderID INTEGER,
                          Step TEXT, Status TEXT, Reason TEXT);
    """)

    for customer_id in range(1, 3001):
        conn.execute("INSERT INTO Collaborator VALUES (?, ?)",
                     (customer_id, rng.choice(states)))

    rma_id = 1
    for order_id in range(1, 6001):
        customer_id = rng.randint(1, 3000)
        sku, description, return_chance = rng.choice(skus)
        conn.execute("INSERT INTO Orders VALUES (?, ?, ?, ?)",
                     (order_id, customer_id, sku, description))
        if rng.random() < return_chance:
            conn.execute("INSERT INTO RMA VALUES (?, ?, ?, ?, ?)",
                         (rma_id, order_id, rng.choice(steps),
                          rng.choice(statuses), rng.choice(reasons)))
            rma_id += 1
    conn.commit()
    return conn

def fetch(connection, mode, name, params=None):
    """Run one named query and return the result as a pandas DataFrame."""
    mysql_sql, demo_sql = QUERIES[name]
    if mode == "mysql":
        from sqlalchemy import text
        result = connection.execute(text(mysql_sql), params or {})
        return pd.DataFrame(result.fetchall(), columns=list(result.keys()))
    return pd.read_sql(demo_sql, connection, params=params)

def summarize_states(states_df):
    """Basic summary statistics for returns by state."""
    counts = states_df["AmountOfReturns"].astype(float)
    return {
        "States with returns": int(len(states_df)),
        "Total returns": int(counts.sum()),
        "Average per state": round(counts.mean(), 1),
        "Median per state": round(counts.median(), 1),
        "Std. deviation": round(counts.std(), 1),
        "Highest": f'{states_df.iloc[0]["State"]} ({int(states_df.iloc[0]["AmountOfReturns"])})',
        "Lowest": f'{states_df.iloc[-1]["State"]} ({int(states_df.iloc[-1]["AmountOfReturns"])})',
    }


def build_findings(states_df, sku_df, reason_df):
    """Turn the numbers into a few plain-English findings."""
    sku_df = sku_df.copy()
    sku_df["ReturnRatePct"] = sku_df["ReturnRatePct"].astype(float)
    worst = sku_df.iloc[0]
    best = sku_df.iloc[-1]
    findings = [
        f'{states_df.iloc[0]["State"]} has the most returns '
        f'({int(states_df.iloc[0]["AmountOfReturns"])}).',
        f'{worst["SKU"]} has the highest return rate at {worst["ReturnRatePct"]}% '
        f'of its orders.',
        f'{best["SKU"]} has the lowest return rate at {best["ReturnRatePct"]}%.',
    ]
    if len(reason_df) > 0:
        findings.append(f'The most common return reason is '
                        f'"{reason_df.iloc[0]["Reason"]}" '
                        f'({int(reason_df.iloc[0]["AmountOfReturns"])} returns).')
    return findings

def save_bar_chart(labels, values, title, xlabel, ylabel, filename, horizontal=False):
    fig, ax = plt.subplots(figsize=(9, 5))
    if horizontal:
        ax.barh(labels[::-1], values[::-1], color=NAVY)
        ax.set_xlabel(ylabel)
        ax.set_ylabel(xlabel)
    else:
        ax.bar(labels, values, color=NAVY)
        ax.set_xlabel(xlabel)
        ax.set_ylabel(ylabel)
        plt.setp(ax.get_xticklabels(), rotation=45, ha="right")
    ax.set_title(title)
    fig.tight_layout()
    path = os.path.join(OUTPUT_DIR, filename)
    fig.savefig(path, dpi=110)
    plt.close(fig)
    return filename

def write_html_report(mode, summary, findings, tables, charts, top_state, top_state_df):
    banner = ""
    if mode == "demo":
        banner = ('<p class="demo"><strong>DEMO DATA:</strong> this report was built from '
                  'made-up sample data, not the real QuantigrationUpdates database.</p>')

    summary_rows = "".join(
        f"<tr><td>{html.escape(str(k))}</td><td>{html.escape(str(v))}</td></tr>"
        for k, v in summary.items())
    findings_list = "".join(f"<li>{html.escape(f)}</li>" for f in findings)
    chart_tags = "".join(
        f'<h3>{html.escape(title)}</h3><img src="{html.escape(fname)}" alt="{html.escape(title)}">'
        for title, fname in charts)
    table_sections = "".join(
        f"<h3>{html.escape(title)}</h3>{df.to_html(index=False, escape=True)}"
        for title, df in tables)
    state_detail = (f"<h3>Returns by product in {html.escape(str(top_state))}</h3>"
                    + top_state_df.to_html(index=False, escape=True))

    page = f"""<!DOCTYPE html>
<html lang="en"><head><meta charset="utf-8">
<title>RMA Returns Report</title>
<style>
 body {{ font-family: Arial, sans-serif; max-width: 900px; margin: 30px auto; color: #222; }}
 h1, h2, h3 {{ color: {NAVY}; }}
 table {{ border-collapse: collapse; margin-bottom: 20px; }}
 th, td {{ border: 1px solid #ccc; padding: 6px 10px; text-align: left; }}
 th {{ background: #e8ecf8; }}
 img {{ max-width: 100%; }}
 .demo {{ background: #fff3cd; padding: 10px; border: 1px solid #e0c36a; }}
</style></head><body>
<h1>RMA Returns Report</h1>
<p>Generated {datetime.now().strftime("%Y-%m-%d %H:%M")}</p>
{banner}
<h2>Key findings</h2><ul>{findings_list}</ul>
<h2>Summary of returns by state</h2><table>{summary_rows}</table>
<h2>Charts</h2>{chart_tags}
<h2>Details</h2>{table_sections}{state_detail}
<h2>Limitations</h2>
<p>This report counts every RMA record as a return. The data does not say whether a
return was caused by the product itself, shipping damage, or customer preference, so

</body></html>"""

    path = os.path.join(OUTPUT_DIR, "returns_report.html")
    with open(path, "w", encoding="utf-8") as f:

def top_count(value):
    """argparse helper: --top must be a whole number from 1 to 50."""
    number = int(value)
    if number < 1 or number > 50:
        raise argparse.ArgumentTypeError("--top must be between 1 and 50")
    return number


def main():
    parser = argparse.ArgumentParser(description="Automated RMA returns report")
    parser.add_argument("--mode", choices=["demo", "mysql"], default="demo")
    parser.add_argument("--top", type=top_count, default=10,
                        help="how many states to show in the chart (1-50)")
    args = parser.parse_args()

    os.makedirs(OUTPUT_DIR, exist_ok=True)

    if args.mode == "demo":
        print("DEMO MODE: using generated sample data, not the real database.")
        connection = build_demo_database()
    else:
        connection = connect_mysql()

    try:
        states_df = fetch(connection, args.mode, "returns_by_state")
        sku_df = fetch(connection, args.mode, "return_rate_by_sku")
        reason_df = fetch(connection, args.mode, "returns_by_reason")

        if states_df.empty or sku_df.empty:
            sys.exit("No return data found. Check that the tables are loaded.")

        top_state = states_df.iloc[0]["State"]
        top_state_df = fetch(connection, args.mode, "returns_by_sku_for_state",
                             {"state": top_state})
    finally:
        connection.close()  # always leave the connection closed

    sku_df["ReturnRatePct"] = sku_df["ReturnRatePct"].astype(float)

    summary = summarize_states(states_df)
    findings = build_findings(states_df, sku_df, reason_df)

    top = states_df.head(args.top)
    charts = [
        ("Top states by number of returns",
         save_bar_chart(top["State"].tolist(), top["AmountOfReturns"].astype(float).tolist(),
                        f"Top {len(top)} states by returns", "State", "Returns",
                        "returns_by_state.png")),
        ("Return rate by product",
         save_bar_chart(sku_df["SKU"].tolist(), sku_df["ReturnRatePct"].tolist(),
                        "Return rate by product (% of that product's orders)",
                        "Product SKU", "Return rate (%)", "return_rate_by_sku.png",
                        horizontal=True)),
    ]
    tables = [
        ("Return rate by product", sku_df),
        ("Returns by reason", reason_df),
    ]

    path = write_html_report(args.mode, summary, findings, tables, charts,
                             top_state, top_state_df)
    print("Report written to", path)
    for finding in findings:
        print(" -", finding)


if __name__ == "__main__":
    main()

"""
test_returns_report.py
ENHANCEMENT (Milestone Four -- Databases)

Tests for returns_report.py. They run against the in-memory demo database,
so no MySQL server is needed.

Run with:  python -m unittest test_returns_report -v
"""

import argparse
import unittest

import returns_report as rr


class ReturnsReportTests(unittest.TestCase):

    def setUp(self):
        self.conn = rr.build_demo_database()

    def tearDown(self):
        self.conn.close()

    def test_state_totals_match_rma_row_count(self):
        # Every RMA row belongs to exactly one state, so the totals must match.
        states = rr.fetch(self.conn, "demo", "returns_by_state")
        rma_rows = self.conn.execute("SELECT COUNT(*) FROM RMA").fetchone()[0]
        self.assertEqual(int(states["AmountOfReturns"].sum()), rma_rows)

    def test_states_sorted_highest_first(self):
        states = rr.fetch(self.conn, "demo", "returns_by_state")
        counts = states["AmountOfReturns"].tolist()
        self.assertEqual(counts, sorted(counts, reverse=True))

    def test_return_rate_is_between_0_and_100(self):
        skus = rr.fetch(self.conn, "demo", "return_rate_by_sku")
        self.assertTrue((skus["ReturnRatePct"] >= 0).all())
        self.assertTrue((skus["ReturnRatePct"] <= 100).all())

    def test_return_rate_uses_each_products_own_orders(self):
        # Recompute one SKU's rate by hand and compare.
        skus = rr.fetch(self.conn, "demo", "return_rate_by_sku")
        row = skus.iloc[0]
        orders = self.conn.execute(
            "SELECT COUNT(*) FROM Orders WHERE SKU = ?", (row["SKU"],)).fetchone()[0]
        returns = self.conn.execute(
            "SELECT COUNT(*) FROM RMA r JOIN Orders o ON o.OrderID = r.OrderID "
            "WHERE o.SKU = ?", (row["SKU"],)).fetchone()[0]
        self.assertAlmostEqual(row["ReturnRatePct"], round(returns * 100.0 / orders, 2), places=2)

    def test_sql_injection_attempt_is_treated_as_plain_text(self):
        # A hostile "state" value must not be able to run extra SQL.
        evil = "x'; DROP TABLE RMA; --"
        result = rr.fetch(self.conn, "demo", "returns_by_sku_for_state", {"state": evil})
        self.assertTrue(result.empty)  # no state has that name
        still_there = self.conn.execute("SELECT COUNT(*) FROM RMA").fetchone()[0]
        self.assertGreater(still_there, 0)  # table survived

    def test_top_count_rejects_out_of_range_values(self):
        with self.assertRaises(argparse.ArgumentTypeError):
            rr.top_count("0")
        with self.assertRaises(argparse.ArgumentTypeError):
            rr.top_count("51")
        self.assertEqual(rr.top_count("10"), 10)


if __name__ == "__main__":
    unittest.main()
