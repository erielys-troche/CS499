Choosing the right structure for the job, and proving it works.

I am just finishing my B.S. in Computer Science at Southern New Hampshire University with a focus on data science and algorithms, and I am looking forward to landing my first developer job. This site is my capstone ePortfolio. Below is my self-assessment, three projects, and a code review video.

Where I am as a developer

When I started the degree, I could only make a program run. Now I can explain why I built it a certain way, what the trade-offs were, and how I would check that it works. The capstone made that clear, because I took three older class projects and had to look at them like someone else’s code. The biggest change for me is that in the process of learning, I stopped thinking “does it work?” and started asking “what happens when it breaks, grows, or gets attacked?”

Working in groups

Working in group environments provided a great experience and growth. Seeing how group projects and group dynamics in general are the most common in a real work environment, having these experiences served as a crucial learning experience. In the capstone, I practiced the same habits in my work. I wrote commit messages, a README for database projects, and unit tests so each developer could pick up my code without me having to explain it.

Communicating with different audiences

I had to explain the same work in different ways. The code review video is for other developers. It walks them through what each file does and how I would enhance them. The database report is for a product manager, so it leads with findings like “California has the most returns” instead of SQL, and it has a limitations section saying the data can’t prove why returns happen.

Data structures and algorithms

My Course Planner started as a plain binary search tree. If you insert courses in sorted order, it turns into a linked list, and every search becomes O(n). I replaced it with an AVL tree that rotates itself back into balance, so search and insert stay O(log n). I also built a directed graph of prerequisites and used Kahn’s algorithm to find a valid course order and to catch circular prerequisites, which the old code could not do. The trade-off is that the AVL is more code and does extra work on every insert, but for data that gets searched a lot, it’s worth it. See the full write-up.

Software design and databases

For Global Rain I used the Strategy pattern so fee rules live in their own classes. Adding a new pet type now means writing one new class instead of editing old ones. For the database project, I added indexes on the columns I actually filter on, stored procedures, and a Python script that builds the report automatically instead of me pasting screenshots into Word. Security mindset

For the database work, I used parameterized queries, a read-only account that can only run the report procedures, and environment variables for the login so no password sits in the code. One of my tests tries a DROP TABLE injection through the state field and confirms the table survives. I also try to check my assumptions: I originally planned to index foreign keys, then realized from my own DESCRIBE output that MySQL had already done it, and changed the plan.

How the artifacts fit together
